# Исправление логики парсера тренировок и автоматической генерации сетов

## Что исправлено

### 1. Очистка названия упражнения (Title Cleanup)
- **Проблема**: Хвост параметров (например, `— 4х8-10 (40–42.5 кг)`) прилипал к названию, если дефис не отделялся строго или если упражнение содержало внутренние дефисы (`EZ-штанги`, `Пек-Дек`).
- **Решение**: Регулярное выражение разделяет строку по разделителю `\s+[-—–]\s+|\s*[-—–]\s*(?=\d+\s*[xх*×])`.
  - Все составные названия с дефисом без пробелов (`EZ-штанга`, `Пек-Дек`, `Т-гриф`) аккуратно сохраняются.
  - Весь хвост после разделителя отправляется в отдельный парсер параметров.

### 2. Точный парсинг подходов, повторений и весов
- **Подходы и повторения**:
  - Извлекаются `sets_count` (int), `reps_min` и `reps_max` (int), а также строковый диапазон `target_reps` (например, `"8-10"`).
  - По умолчанию для сетов берется верхняя планка диапазона `reps_default = reps_max` (например, `10`).
- **Вес**:
  - Конструкции вида `по 22.5–25 кг с каждой стороны` распознаются и удваиваются (для Смита/штанги: `25.0 * 2 = 50.0 кг`).
  - Вес из скобок `(40–42.5 кг)`, `(гантель 12–14 кг)` берется по верхнему числу (например, `42.5 кг`, `14.0 кг`).
  - Веса с единицей `6.25 кг` или `80кг` парсятся корректно без потерь дробной части.

### 3. Автоматическая генерация сетов в активную тренировку
- **База данных и схемы**:
  - В модель `ProgramExercise` и таблицу `program_exercises` добавлена колонка `target_weight_kg: Float`.
  - В схему Pydantic `ProgramExerciseOut` добавлено поле `target_weight_kg: Optional[float]`.
- **Генерация сетов при старте**:
  - При вызове `POST /api/workouts/start` с `program_day_id` бэкенд автоматически создает все `sets_count` подходов (а не 1 пустой с нулем).
  - Каждый сет создается с реальными параметрами: `set_number` (1..N), `weight_kg = target_weight_kg`, `reps = target_reps`, `is_completed = false`.
  - Во фронтенде `LiveWorkoutView.tsx` логика также дублирует автозаполнение сетов для любых начатых тренировок дня.
